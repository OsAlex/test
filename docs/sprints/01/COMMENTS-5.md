### Q3a. ФОИВ код — `"030"` для всех групп ЧЗ

**Однозначный ответ: `1262 = "030"` для ВСЕХ товарных групп ЧЗ.**

Обоснование:
- `030` — код **ФНС** как оператора маркировки.
- Другие коды ФОИВ (041 — Минпромторг, 048 — РАР, 049 — Росздравнадзор) применяются **только** для систем, не относящихся к ЧЗ (ЕГАИС, МДЛП).
- В методичке v17 (и всех предыдущих) для ЧЗ всегда `1262="030"`.

**Не нужно ждать ответа Атол по этому пункту.** Зафиксировать в SPEC как факт.

---

### Q3b. Формат даты 1263

**Однозначный ответ: `ДД.ММ.ГГГГ`.**

Обоснование:
- Приказ ФНС ЕД-7-20/662@, таблица реквизитов: тег 1263 «Дата документа основания» — формат **ДД.ММ.ГГГГ**.
- Пример в PIOT §6.3: `"21.11.2023"` — именно ДД.ММ.ГГГГ.
- ISO (`YYYY-MM-DD`) используется в **других** полях API ГИС МТ (`expireDate`, `productionDate`), но **не в теге 1263**.

**Действие:** в SPEC заменить «уточнить формат» на «формат ДД.ММ.ГГГГ (по приказу ФНС)».

### 2.1. `errorCode` маппинг неверен 🔴

|-----|----------|-------|
| 0 | Нет ошибки | INFO |
| 1–9 | Ошибки валидации/крипто/AI | **WARN** |

### 2.2. `marking_check_history` — `NOT NULL` для офлайн-полей 🔴

**§2.2 SPEC:**
```sql
found BOOLEAN NOT NULL,
verified BOOLEAN NOT NULL,
sold BOOLEAN NOT NULL,
is_blocked BOOLEAN NOT NULL,
```

**Проблема:** ЛМ ЧЗ в `/cis/outCheck` **не возвращает** `found`, `verified`. Только `sold`, `isBlocked`, `isGreyGtin`, `gtin`, `mrp`, `smp`.

**Следствие:** при записи офлайн-проверки в БД будет **ошибка NOT NULL constraint**.

**Что делать:**
```sql
found BOOLEAN NULL,
verified BOOLEAN NULL,
sold BOOLEAN NULL,
is_blocked BOOLEAN NULL,
```

Или использовать одно поле `source` для разделения. Явно указать в SPEC: «Поля, недоступные в офлайне, заполняются NULL».

### 2.3. `marking_check_history.status` — семантика от sell_queue 🔴

### 3.7. `marking_sell_queue.status = 'skipped'` — противоречие
