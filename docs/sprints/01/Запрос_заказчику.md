**Действие:** Если у заказчика есть свои norm-act номера/даты для конкретных групп — проставить в `config/marking.php → tag1260.by_group`. Если групп нет в списке — оставить дефолтные значения.
**Блокер для кода:** Нет — можно начать разработку с placeholder-значениями.

### 2. Q2a — Список регионов и часовых поясов точек

**Важно: нельзя просто "оставить Москва всегда".**
Была путаница: `timeZone` — это **постоянный расчетный пояс**, а не место офиса.
- Калининград (UTC+1, код **1**)
- Камчатка (UTC+12, код **11**)
- Если **все точки в Москве** → `timeZone=2` и интерфейс не расширяем
- Если **хотя бы одна точка вне Москвы** → `Cassa::getTimeZone()` с маппингом по ID точки

**Действие:** Необходимо получить у заказчика **фактический список точек** с указанием:
- Город
- Адрес
- ЧЗ ID (1=Калининград, ..., 11=Камчатка)
- Количество касс

**Блокер для кода:** Да — нужно знать, есть ли не-MSK точки. Если есть — нужна реализация `Cassa::getTimeZone()`. Если все MSK — можно сделать MVP с фиксированным `timeZone=2`.

### 3. Q4a — Срок действия sandbox-токена

**Срок истек, proceed based on expiry.**
SPEC.md §1.3.1 документирует правило:
- «Sandbox-токен действителен до `<дата из ЛК>`. Проверка каждые 30 дней. При истечении < 14 дней — алерт.»

**Действие:**
- Зафиксировать дату истечения в проекте
- Вести работу с пониманием истекшего срока
- При следующей проверке (каждые 30 дней) ожидать алерта
- Блокер для кода: Нет — можно начинать development, зная, что токен истёк, и настраиваем алерты

### 5. Официальный JSON Атол — тег 1260

**Формат можно вынести в config.**
Структура уже в SPEC.md §1.5 и config/marking.php:
```php
'tag1260' => [
    'default' => ['1262' => '030', '1263' => '28.12.2018', '1264' => '1955'],
    'by_group' => [...],
],
```
**Действие:** 
- Если есть свои значения для групп ЧЗ — проставить в `by_group`
- Если общих значений достаточно — оставить `default`
- Atol JSON формату соответствует и `default`, и `by_group` варианты

## Итоговые рекомендации по отправке запроса:

**Максимально экономный вариант (разработка может начаться сразу):**

1. **Q1a** — Оставить дефолтные значения в `config/marking.php`. Если группы в списке нет — используем `default`.
2. **Q2a** — **Обязательно получить** список регионов с ЧЗ ID. Без этого не могу 올바льно настроить `timeZone`.
3. **Q4a** — Зафиксировать дату истечения sandbox-токена из ЛК ЧЗ. Развивать работу с пониманием истекшего срока.

**Минимальный набор для старта:** Q2a (рег-он!) + Q4a (термин sandbox).

Можно присылать коротко:
1. Список городов с ЧЗ ID (или подтверждение, что все в Москве → `timeZone=2`)
2. Дата истечения sandbox-токена из ЛК ЧЗ

Остальное (Q1a, формат Atol JSON) можно проставить в конфиг и продолжить разработку.
