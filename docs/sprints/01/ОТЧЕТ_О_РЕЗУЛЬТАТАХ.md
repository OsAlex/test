## 3. Ключевые решения (зафиксированы в SPEC и коде)

| # | Решение | Основание |
|---|---|---|
| 1 | Токен ГИС МТ — из `.env`/`config('marking.api_key')` ИЛИ `POST /api/v3/true-api/auth/permissive-access` (УКЭП). **Никогда не через `/cdn/info`** | Q7 canonical, COMMENTS-7 |
| 2 | HTTP 401 ≠ «CDN упал»: метрика `marking_401_total`, `TokenBrokenException`, офлайн-режим; хост не блокируется | Запрос_заказчику_ответ.md |
| 3 | Порядок операций CDN: `ensureToken → /cdn/info → /cdn/health/check → /codes/check`; X-API-KEY на **всех** запросах | SPEC §3.2 |
| 4 | Блокировка хоста — 15 мин после 3 сбоев; кеш `/cdn/info` 6 ч + джиттер 0–10 мин; барьер гибрида 1.5 c | SPEC §3.2–§3.4 |
| 5 | ProhibitionLevel: `0→INFO, 1–9→WARN (fail), 10→BLOCK, 11→WARN` — финальная таблица | SPEC §1.6 |
| 6 | Батчи ≤100 КМ/КИ (ГИС МТ и ЛМ ЧЗ); `sold(skip, limit)` — выгрузка, **не** подтверждение продажи | SPEC §1.7, §3.6 |
| 7 | Pre-check агрегатов — **только онлайн** (есть `parent_cis` в ответе); агрегат+единицы без онлайн → BLOCK | SPEC §1.6.1, §3.5 |
| 8 | `/cis/return` — после фискализации, до возврата денег; отдельная трасса, не блокирует продажи | SPEC §8 |
| 9 | Очередь продаж: retry 3 раза с backoff, затем `failed` + алерт; статус `return` для проведённых возвратов | SPEC §2.1, §3.4 |
| 10 | `item_id` в истории — NULL allowed; `skip_reason` вместо статуса `skipped` в ENUM | COMMENTS-6/7 |
| 11 | EMERGENCY_TIMEOUT: оба ответа не пришли за 1.5 c → WARN + метрика + алерт при доле >5% за 5 мин | SPEC §3.4, §5 |
| 12 | UI кассира — jQuery/Bootstrap 5 (в проекте нет Vue) | `package.json` |
