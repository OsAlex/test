## 2. Архитектура проверки кодов маркировки

### 2.1 Два режима проверки

```
┌─────────────────────────────────────────────────────────────┐
│                    ПРОВЕРКА КОДОВ МАРКИРОВКИ                   │
├─────────────────────────────────────────────────────────────┤
│  ONLINE (CDN API)                                           │
│  ├── GET /api/v4/true-api/cdn/info          — список CDN    │
│  ├── GET /api/v4/true-api/cdn/health/check  — здоровье CDN  │
│  ├── POST /api/v4/true-api/codes/check      — проверка кодов│
│  └── History API (create/receive)           — выгрузка истории│
│                                                             │
│  OFFLINE (ЛМ ЧЗ — Local Module)                             │
│  ├── POST /api/v2/init                          — инициализация│
│  ├── GET  /api/v2/status                        — статус      │
│  ├── POST /api/v2/cis/outCheck                  — проверка КИ │
│  ├── POST /api/v2/greyList                      — серые списки│
│  ├── POST /api/v2/cis/sell                      — регистр. продажи│
│  ├── POST /api/v2/cis/return                    — возврат     │
│  └── GET  /api/v2/cis/sold                      — список проданных│
└─────────────────────────────────────────────────────────────┘
```

### 2.2 Сценарий проверки перед продажей (п.5 методички)
1. Кассир сканирует Data Matrix
2. **Параллельно**: КМ → ГИС МТ (`/codes/check`), КИ → ЛМ ЧЗ (`/cis/outCheck`)
3. Если `sold=true` из ЛМ ЧЗ → **запретить продажу** (независимо от онлайн)
4. Если онлайн-ответ не за **1.5 сек** → решение по оффлайн-ответу
5. Проверить ответ на соответствие **случаям запрета** (таблица в п.4)
6. При запрете → уведомить кассира
7. После фискализации → добавить КИ в БД проданных (`/cis/sell`)
8. При возврате → удалить КИ (`/cis/return`)

## 3. Анализ текущего кода проекта

### 3.1 Models/Check.php — Модель чека

**Текущая функциональность:**
- Создание чеков разных типов (аванс, приход, возврат, коррекция)
- Генерация JSON для Атол (ФФД 1.2)
- Отправка чека на кассу (HTTP POST на IP кассы)
- Получение фискальных признаков (ФПД, ФДН, ФРН, смена)
- Email-уведомления клиенту
- Валидация блокируемых товаров (ID 4487, 4488)

**Что НЕ реализовано (требуется для PIOT):**
| Функция | Статус |
|---------|--------|
| Проверка КМ в ГИС МТ (онлайн) | ❌ Отсутствует |
| Проверка КИ в ЛМ ЧЗ (офлайн) | ❌ Отсутствует |
| Выделение КИ из КМ | ❌ Отсутствует |
| Заполнение тега 1260 (отраслевой реквизит) | ❌ Отсутствует |
| Логика запрета продажи (таблица п.4) | ❌ Отсутствует |
| Регистрация продажи в ЛМ ЧЗ (`/cis/sell`) | ❌ Отсутствует |
| Возврат в ЛМ ЧЗ (`/cis/return`) | ❌ Отсутствует |
| Обработка `isBlocked`, `ogvs`, `smp`, `mrp` | ❌ Отсутствует |
| Работа с CDN-площадками (выбор, кэш, переключение) | ❌ Отсутствует |
| Аутентификация (токен X-API-KEY) | ❌ Отсутствует |

### 3.2 Service/CheckService.php — Сервис чеков

**Текущая функциональность:**
- `makeCheckData()` — создание данных чека
- `createCheck()` — создание чека по ID оплаты
- `makeJson()` — перегенерация JSON
- `sendCheck()` — отправка на кассу
- `resetCheck()` — сброс чека
- `runAllAction()` — полный цикл: JSON → отправка → запрос данных → сохранение в АТOL

**Требуемые изменения:**
- Добавить шаг **проверки КМ/КИ** перед генерацией JSON
- Интегрировать логику **онлайн/офлайн** переключения
- Добавить **заполнение тега 1260** в JSON чека
- Вызывать `/cis/sell` после успешной фискализации

## 6. Критические моменты из документации

### 6.1 Тайминги и таймауты
| Параметр | Значение | Источник |
|----------|----------|----------|
| Таймаут онлайн-проверки | 1.5 сек (за 3 раза подряд → блокировка 15 мин) | п.1.4.3, 1.6 |
| Таймаут `/cdn/health/check` | 2 сек (до 10 при проблемах) | п.1.4 |
| Обновление списка CDN | не ранее 6ч, не позднее 7ч | п.1.4.2 |
| Синхронизация ЛМ ЧЗ | 72 часа без синхронизации → `sync_error` | п.2.1 |
| Инициализация ЛМ ЧЗ | потеря связи >15 мин → `not_configured` | п.2.7 |
| Авто-инициализация ЛМ ЧЗ | 10 дней офлайна → авто-инит после восстановления | v17 изменения |

### 6.2 Специфика табачной продукции
- **МРЦ** в КМ пачки: символы [22..25], декодирование 80-символьным алфавитом
- **ЕМЦ (smp)** — только потребительская упаковка, в копейках
- **Серая зона (grayZone)** — табак с `grayZone=true` продажа разрешена при `realizable=false`
- **Минимальная цена (mrp)** — проверка для табака (id=3), АТП (id=12), НСП (id=16)

### 6.3 Тег 1260 (Отраслевой реквизит)
```
Тег 1260:
  1262 = "030"                    # ИД ФОИВ
  1263 = "21.11.2023"             # Дата документа основания
  1264 = "1944"                   # Номер документа основания
  1265 = "UUID=...&Time=...&Inst=...&Ver=..."  # Значение
```
