## 1. Онлайн-проверка (CDN API)

### 1.1 Хосты

- Тестовый контур: `https://markirovka.sandbox.crptech.ru`
- Продуктивный контур: `https://cdn.crpt.ru`
- Порт по умолчанию: 443

### 1.2 Аутентификация (получение токена)

**Метод:** `POST /api/v3/true-api/auth/permissive-access`
- Тело: `{ "data": "<BASE64-строка, подписанная УКЭП>" }`
- Ответ: `{ "access_token", "id_token", "expires_in", "token_type" }`
- `access_token` используется как `X-API-KEY` в заголовках.

**Альтернатива:** получить токен вручную в личном кабинете ГИС МТ (раздел профиль → «Токен для ККТ»).

**Важно:**
- Токен действует до **1 октября 2026 года**.
- Один токен на ИНН, используется на всех кассах.
- Публикация токена в открытых источниках → блокировка Оператором.
- Целевая схема аутентификации — через фискальный накопитель.
- Токен можно получить с обезличенным сертификатом.

### 1.3 Получение списка CDN-площадок

**Метод:** `GET /api/v4/true-api/cdn/info`
- Заголовок: `X-API-KEY`
- Ответ: `{ "code": 0, "description": "ok", "hosts": [ {"host": "https://cdn01.am.crptech.ru"}, ... ] }`
- Порт по умолчанию 443.

### 1.4 Проверка состояния CDN-площадки

**Метод:** `GET /api/v4/true-api/cdn/health/check` (на конкретную CDN-площадку)
- Заголовки: `Content-Type: application/json`, `Connection: close`, `X-API-KEY`
- Ответ: `{ "code": 0, "description": "ok", "avgTimeMs": <ms> }`
- `avgTimeMs` — справочное, не используется для приоритезации.
- **Таймаут:** рекомендуется 2 секунды (до 10 с при проблемах связи). При таймауте — пометить площадку как недоступную на 15 минут.
- **Соединение:** устанавливать HTTPS, выполнить запрос и сразу закрывать соединение после ответа.

### 1.5 Выбор и кэширование CDN-площадок

1. Получить список через `/cdn/info`.
2. Проверить состояние каждой через `/cdn/health/check`.
3. Приоритет — по минимальной latency (время ответа).
4. Кэш хранить до успешного обновления.
5. Обновлять список не Earlier чем через 6 часов, не позже 7 часов.
6. При обновлении добавлять случайную задержку 0–10 минут.
7. При недоступности `/cdn/info` использовать кэш; если кэша нет — дефолтный список `cdn01.crpt.ru` … `cdn11.crpt.ru`.

### 1.6 Переключение между CDN-площадками

| HTTP-код | Действие |
|---|---|
| 4xx (кроме 401, 429) | Ошибка в запросе, не повторять |
| 401 | Ошибка авторизации — проверить токен (рекомендуется проверить через `/cdn/info`) |
| 429 | Повторить запрос; при повторной ошибке — пометить площадку на 15 мин и переключиться |
| 5xx | Повторить запрос; при повторной ошибке — пометить на 15 мин и переключиться |
| 5xx с кодом 5000 в теле | Не пометять площадку как недоступную — повторить запрос; при повторной ошибке — продавать без онлайн-проверки (с оффлайн, если она обязательна) |

- При 3 подряд неудачных ответах за 1.5 сек — пометить площадку на 15 мин.
- После блокировки (15 мин) перед разблокировкой проверять `/cdn/health/check`.

### 1.7 Метод проверки кодов (онлайн)

**Метод:** `POST /api/v4/true-api/codes/check`

Тело:
```json
{
  "codes": ["<КМ>"],
  "fiscalDriveNumber": "16 цифр",
  "timeZone": 1..11
}
```
- `codes` — полный КМ с крипто-подписи; символ GS (ASCII 029) экранировать как `\u001d`.
- `timeZone` — по умолчанию 2 (МСК). Влияет на `smp` и `mrp`.

Ответ (200):
```json
{
  "code": 0,
  "description": "ok",
  "codes": [{
    "cis": "<КМ>",
    "valid": true,
    "printView": "<КМ без крипто-подписи>",
    "gtin": "<код товара>",
    "groupIds": [15],
    "verified": true,
    "found": true,
    "realizable": false,
    "utilised": true,
    "isBlocked": false,
    "expireDate": "2024-08-16T00:00:00.000Z",
    "productionDate": "2023-08-16T00:00:00.000Z",
    "errorCode": 0,
    "isTracking": false,
    "sold": true,
    "packageType": "UNIT",
    "producerInn": "7731376812",
    "grayZone": false,
    "soldUnitCount": 49000,
    "innerUnitCount": 50000
  }],
  "reqId": "UUID",
  "reqTimestamp": <ms UTC>
}
```

### Коды ошибок errorCode
0 — нет ошибки; 1 — ошибка валидации КМ; 2 — нет GTIN; 3 — нет серийного номера; 4 — недопустимые символы; 5–7 — ошибка крипто-подписи; 8 — не верифицирован в стране эмитента; 9 — AI не поддерживаются; 10 — КМ не найден в ГИС МТ; 11 — не найден в трансгране.

### Товарные группы (groupIds)
1 — одежда/бельё; 2 — обувь; 3 — табак; 4 — духи; 5 — шины; 6 — фотокамеры; 8 — молочка; 9 — велосипеды; 10 — медицинские изделия; 12 — альтернативный табак; 13 — упакованная вода; 14 — мех; 15 — пиво/слабоалкоголь; 16 — никотинсодержащая; 17 — БАДы; 19 — антисептики; 20 — корма для животных; 21 — морепродукты; 22 — безалкогольное пиво; 23 — соки/безалкогольные напитки; 26 — ветпрепараты; 27 — игрушки; 28 — радиоэлектроника; 32 — консервы; 33 — растительные масла; 35 — косметика/бытовая химия; 37 — бакалейные товары; 39 — стройматериалы; 43 — моторные масла; 45 — сладости.

### Типы упаковки
UNIT — единица товара; GROUP — групповая; BUNDLE — комплект; PRODUCT_SET — набор.

### Ограничения
Метод /codes/check — только для проверки перед розничной продажей (п.13 Правил №1944).

### Рекомендации по соединению
- HTTPS, использовать tcp-keepalive, удерживать соединение на время чека.
- Idle timeout на стороне ГИС МТ — 180 сек.
- Для /cdn/health/check — соединение закрывать сразу после ответа.

### 1.8 История ответов

**Создать выгрузку:** `POST /api/v4/true-api/codes/check/history/create`
- Тело: `{ "requests": [{ "reqId", "reqTimestamp" }] }` (до 100 штук)
- Ответ: `{ "queryId": "UUID" }` (статус 202)
- Ограничение: 1 раз в минуту.

**Получить результат:** `GET /api/v4/true-api/codes/check/history/receive?queryId=<UUID>`
- Ответ: `{ "queryId", "queryStatus": "DONE"|"IN_PROGRESS", "result": [...] }`
- При IN_PROGRESS — повторить через 30+ сек.
- Ограничение: 1 раз в минуту.
- `searchStatus`: "FOUND" / "NOT_FOUND".

## 2. Офлайн-проверка (ЛМ ЧЗ)

### 2.1 Общее
- Офлайн-проверка допускается **только** после попытки онлайн и ожидания 1.5 сек.
- Проверяется **КИ** (без крипто-подписи), для табака — без МРЦ.
- ЛМ ЧЗ устанавливается **один экземпляр** на торговый объект (на ИНН).
- При отсутствии синхронизации 72 часа — проверка через ЛМ ЧЗ невозможна (статус `sync_error`).
- Лицензиат обязан своевременно обновлять ЛМ ЧЗ.

### 2.2 Хост ЛМ ЧЗ
`http://127.0.0.1:5995`

### 2.3 Аппаратные требования
- CPU: 4 ядра
- RAM: 4 Гб
- Диск: 150 Мб (развёрнутый), плюс место под БД заблокированных сведений.

### 2.4 Поддерживаемые ОС
| ОС | x86 | x86_64 | ARM7 | ARM64 |
|---|---|---|---|---|
| Windows 7 Ultimate | — | + | — | — |
| Windows 10 | + | + | — | — |
| Windows 11 | + | + | — | — |
| Ubuntu 22.04 | — | + | — | + |
| Debian 11 | — | + | — | + |
| Android 5–15 | — | — | + | + |

### 2.5 Дистрибутивы
https://честныйзнак.рф/local-module

### 2.6 Установка
- Продуктивный контур: `https://rsapi.crpt.ru`
- Тестовый контур: `https://suz-rsapi.sandbox.crptech.ru`
- Задать логин/пароль (Basic auth).
- Сервер конфигурации: `194.0.209.18` (TCP/443) — должен быть открыт.

### 2.7 Инициализация
**Метод:** `POST /api/v2/init`
- Заголовки: `Authorization: Basic <base64(login:password)>`, `X-ClientId: <номер ФН>`
- Тело: `{ "token": "<x-api-key>", "clearSold": true|false }`
- `clearSold` — признак удаления БД проданных товаров.
- Используется только для первичной настройки.
- При потере связи на 15 минут — статус `not_configured`.
- При 10 днях без связи — автоматическая инициализация после восстановления.
- Логи:
  - Windows 32: `C:\Program Files (x86)\Regime\var\log`
  - Windows 64: `C:\Program Files\Regime\var\log`
  - Ubuntu/Debian: `/var/log/regime/`

### 2.8 Проверка статуса
**Метод:** `GET /api/v2/status`
- Ответ: `{ version, status, serviceUrl, operationMode, name, lastUpdate, lastSync, inst, inn, dbVersion, dbState, isGreyGtin }`
- `status`: `not_configured`, `initialization`, `ready`, `failure`, `sync_error`.
- `dbState`: `{ min_price, blocked_gtin, blocked_cis }` с `docCount`.
- При 72 часа без синхронизации (с `lastSync`) — `sync_error`.

### 2.9 Проверка КИ (оффлайн)
**Метод:** `POST /api/v2/cis/outCheck`
- Заголовки: `Authorization: Basic <...>` или `Authorization: Token <UUID>` (через ТСПИоТ), `X-ClientId`
- Тело: `{ "cis_list": [{ "cis": "<КИ>", "pg": <ТГ> }] }`
- Ответ: `{ results: [{ reqId, reqTimestamp, inst, version, codes: [{ cis, isBlocked, isGreyGtin, gtin, sold, mrp, smp }] }] }`
- При статусе ЛМ ЧЗ, отличном от `ready` — ошибка 400:
  - `errorCode: 4045` (для `not_configured`/`initialization`)
  - `errorCode: 4050` (для `sync_error`)
- Рекомендуется логировать запросы и ответы.

### 2.10 Вспомогательные методы

**Активация «серых списков GTIN»:** `POST /api/v2/greyList`
- Тело: `{ "enableGreyList": true }`
- Позволяет хранить GTIN вместо КИ ( экономия диска).
- При `isBlocked=true & isGreyGtin=true` — проверка возможна **только в режиме онлайн**.
- При инициализации с опцией — в `/api/v2/init` добавить `"enableGreyList": true`.

**Регистрация продажи:** `POST /api/v2/cis/sell`
- Тело: `{ "cis_list": ["<КИ>", ...] }`
- Ответ: `{ results: [{ success, cis }] }` (201)
- КИ добавляются в БД проданных товаров (удаляются через 30 дней).
- При частичной продаже — добавлять только после реализации последней части.
- Рекомендуется резервное копирование БД.

**Возврат товаров:** `POST /api/v2/cis/return`
- Тело: `{ "cis_list": ["<КИ>", ...] }`
- Ответ: `{ results: [{ success, cis }] }` (200)
- Удаляет КИ из БД проданных товаров.

**Список проданных товаров:** `GET /api/v2/cis/sold?skip=0&limit=100`
- Ответ: `{ total_count, cis_list: [...] }`
- `limit` до 1000.
- Используется для резервного копирования.

### 2.11 Выделение КИ из КМ
- Для всех товарных групп, кроме табака — разделить КМ по первому разделителю GS (ASCII 029, `\u001d`).
- Пример: `01048657365749062155esJWe\u001d93dGVz` → КИ: `01048657365749062155esJWe`
- Для табачной продукции (29 символов) — первые 21 символ (GTIN+serial), без МРЦ.
- Пример: `00000046233219!SX-RqRADpU7Cev` → КИ: `00000046233219!SX-RqR`

## 3. Фискальный документ «Уведомление о реализации»

При продаже маркированного товара в отраслевом реквизите (тег 1260) фиксируется факт и время проверки.

Тег 1260 содержит:
- 1262 — идентификатор ФОИВ: `030`
- 1263 — дата документа основания: `21.11.2023`
- 1264 — номер документа основания: `1944`
- 1265 — значение отраслевого реквизита:
  - Онлайн: `UUID=<reqId>&Time=<reqTimestamp>`
  - Офлайн: `UUID=<reqId>&Time=<reqTimestamp>&Inst=<inst>&Ver=<version>`

Если проверки не было или ответ не получен — тег 1260 не заполняется (до введения обязательных требований по оффлайн).

При корректировке:
- Если в исходном чеке была проверка — указывать те же данные.
- Если проверка появилась при корректировке — указать данные на момент корректировки.
- Скорректировать «Продажа без проверки КМ» нельзя.

## 4. Случаи запрета продажи

| № | Случай | Параметр | Условие |
|---|---|---|---|
| 1 | Нет сведений в ГИС МТ | found / utilised | `found=false` или `utilised=false` |
| 2 | Нарушение формата/структуры КМ | verified | `verified=false` |
| 3 | Выведен из оборота | sold | `sold=true` |
| 4 | Блокировка по решению ОГВ | isBlocked | `isBlocked=true` (огvs указывает ОГВ) |
| 5 | Нет сведений о вводе в оборот | realizable | `realizable=false` и `sold=false` (не для табака в серой зоне) |
| 6 | Просрочен | expireDate | дата проверки >= expireDate (для табака — сравнивать с локальным временем без приведения к часовому поясу) |
| 7 | Цена ≠ МРЦ (табак) | МРЦ из КМ | цена продажи ≠ МРЦ (в копейках, AI 8005) |
| 8 | Цена ниже ЕМЦ (табак) | smp | цена < smp |
| 9 | Цена ниже МЦ (НСП) | mrp | цена < mrp |
| 10 | Цена ниже МЦ (вода, пиво, духи, одежда, шины) | mrp | цена < mrp |
| 11 | Прекращение/признание РД недействительным | isBlocked + ogvs=RD | `isBlocked=true` и `ogvs` содержит RD |
| 12 | Аннулированный ВСД | isBlocked + ogvs=VETRF | `isBlocked=true` и `ogvs` содержит VETRF |

## 5. Сценарий проверки перед продажей

1. Кассир сканирует Data Matrix.
2. КМ → в ГИС МТ (`/codes/check`), параллельно КИ → в ЛМ ЧЗ (`/cis/outCheck`).
3. Если `sold=true` из ЛМ ЧЗ — запретить продажу, независимо от онлайн-ответа.
4. Если онлайн-ответ не за 1.5 сек — принимать решение по оффлайн-ответу.
5. Проверить ответ на соответствие случаям запрета.
6. При запрете — уведомить кассира.
7. После фискализации — добавить КИ в БД проданных товаров (`/cis/sell`).
8. При возврате — удалить КИ (`/cis/return`).

Примечания:
- Недоступность ЛМ ЧЗ не должна влиять на онлайн-проверку.
- Логировать запросы без ответа за 1.5 сек.

## 6. Рекомендации по дополнительным проверкам

1. Исключить дубли КМ в предчеке (кроме частичной продажи).
2. Контролировать локальную БД проданных товаров — проверять, не продавался ли КИ ранее без ГИС МТ.
3. Проверка одновременной продажи агрегата и его составных единиц:
   - Если в чеке есть `packageType=GROUP`/`PRODUCT_SET` и `packageType=UNIT`, входящие в этот агрегат — заблокировать.
   - Сравнивать `cis` агрегата с `parent` других КМ.

## 7. Аварийная ситуация

- Критерии — в пунктах 55–64 Положения ГИС МТ (постановка №515).
- Оператор оповещает участников в течение 3 часов.
- Во время аварийной ситуации и 3 дня после — проверки допустимости продажи **отключаются**, товар можно продавать без проверок.
- Если методы `/codes/check`, `/cdn/info`, `/cdn/health/check` возвращают код **203** — аварийная ситуация уже введена.
- Проверять наличие оповещения через почту/личный кабинет/сайт.

## 8. Требования к заголовкам запросов

- Кодировка: UTF-8.
- `Content-Type: application/json` (без `charset=windows-1251`).
- Не дублировать информацию в заголовках.
- `X-API-KEY` — в формате UUID, без лишних точек/точек с запятой.
- При нарушении — запросы отклоняются.

## 9. Приложение 1 — Алгоритм кодирования/декодирования МРЦ

Алфавит (80-значная система, индекс → символ):
0:A 1:B 2:C 3:D 4:E 5:F 6:G 7:H 8:I 9:J 10:K 11:L 12:M 13:N 14:O 15:P 16:Q 17:R 18:S 19:T 20:U 21:V 22:W 23:X 24:Y 25:Z 26:a 27:b 28:c 29:d 30:e 31:f 32:g 33:h 34:i 35:j 36:k 37:l 38:m 39:n 40:o 41:p 42:q 43:r 44:s 45:t 46:u 47:v 48:w 49:x 50:y 51:z 52:0 53:1 54:2 55:3 56:4 57:5 58:6 59:7 60:8 61:9 62:! 63:" 64:% 65:& 66:' 67:* 68:+ 69:- 70:. 71:/ 72:_ 73:, 74:: 75:; 76:= 77:< 78:> 79:?

**Кодирование** (МРЦ в копейках):
1. Делить на 80, брать остаток → символ в начало строки.
2. Повторять, пока целая часть > 0.
3. Дополнять слева до 4 символов «A» (индекс 0).

**Декодирование:**
- Для каждого символа (с конца, позиция от 0): `result += index(char) * 80^position`.

**Пример:** МРЦ 14630 коп. → «ACW.».
**Получение МРЦ из КМ пачки:** декодировать символы [22..25] полного КМ.
